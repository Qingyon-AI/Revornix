# 快速开始

<Callout>
	如果你希望先直接体验产品，请访问 <a href='https://app.revornix.com'>https://app.revornix.com</a>。
	**中国境内用户建议改用国内镜像 <a href='https://app.revornix.cn'>https://app.revornix.cn</a>，链路更稳。**
	本页主要用于本地/自部署场景。
</Callout>

<Callout>
	如果你的主业务服务部署在中国大陆，但仍需启用 Google / GitHub 登录，请同时参考 [网关部署](developer/gateway) 页面，把统一公网入口和境外认证 API 一起规划进去。
</Callout>

## 手动部署方式

<Callout>
	Python 侧用 [uv](https://docs.astral.sh/uv/)：`api` 与 `worker` 是同一个 uv
	workspace 的两个成员，共用仓库根的一份 `uv.lock` 和一个 `.venv`。不必给每个服务
	各建一个环境 —— 两者的依赖由同一次解析产出，本来就不会冲突。uv 还会自己下载
	对应版本的 Python，机器上不需要预装。
</Callout>

<Steps>

### 克隆仓库到本地

```shell
git clone git@github.com:Qingyon-AI/Revornix.git
cd Revornix
```

### 安装并且启动基础服务

<Callout>
	如果你本地还没有 Postgres、Redis、Neo4j、MinIO、Milvus，可以直接使用 `docker-compose-local.yaml` 和 `.env.local.example` 启动本地基础依赖层。
</Callout>

<Callout type='warning'>
	注意：如果你本地已经有部分依赖在运行，请按实际情况关闭 `docker-compose-local.yaml` 中对应服务，避免端口冲突或数据串用。
</Callout>

复制样例文件，并结合[Revornix 环境变量章节](environment)按实际需要修改。对于最简单的本地场景，通常最关键的是先设置好 `OAUTH_SECRET_KEY`。

```shell
cp .env.local.example .env.local
```

启动本地基础设施服务。

```shell
docker compose -f ./docker-compose-local.yaml --env-file .env.local up -d
```

### 各大微服务环境变量配置

```shell
cp ./web/.env.example ./web/.env
cp ./api/.env.example ./api/.env
cp ./worker/.env.example ./worker/.env
cp ./gateway/.env.example ./gateway/.env
```

`hot-news` 当前仓库里没有提交 `.env.example`，如果你需要自定义它的配置，可以参考[Revornix 环境变量章节](environment)里的变量说明，手动创建 `hot-news/.env`。

然后分别进入对应服务的环境变量文件进行配置，详情见[Revornix环境变量章节](environment)。

<Callout type='warning'>
	注意：如果你使用手动部署，`OAUTH_SECRET_KEY` 必须在 API 和 Worker 之间保持一致，否则认证和内部调用信任链会失效。
</Callout>

### 启动核心后端服务

<Callout type="info">
不需要手动初始化数据库。API 每次启动都会跑一遍幂等的建表、补列、内置数据填充，
并确保 Milvus 集合存在 —— 全新安装和升级都只要把服务起起来。
</Callout>

`app/`、`api/`、`worker/` 是一个 uv workspace：一份 `uv.lock`、仓库根一个 `.venv`，
两个 Python 服务共用。装一次就够，在**仓库根**执行：

```shell
uv sync --all-packages
uv run --directory api fastapi run main.py --port 8001
```

<Callout type="warn">
`--directory` 不能省。日志路径和读哪份 `.env` 都按工作目录取值，在仓库根直接跑会
读到根目录那份配置 —— 不报错，只是值不对。
</Callout>

### 启动热搜聚集服务

```shell
cd hot-news
pnpm install
pnpm build
pnpm start
```

### 启动 celery 任务序列

```shell
uv run --directory worker playwright install chromium-headless-shell
uv run --directory worker celery -A common.celery.app worker \
  --pool=threads --concurrency=20 --loglevel=info -E
```

### 启动前端服务

```shell
cd web
pnpm install
pnpm build
pnpm start
```

### 启动网关服务

<Callout type="warn">
这一步不能跳过。`web/.env.example` 里的 `NEXT_PUBLIC_API_PREFIX` 指向的是
`http://localhost:8787/api` —— 网关，不是 api 的 8001。跳过它，前端所有请求都会
打在没人监听的端口上，界面满屏 Load failed，而 api 日志里一条请求都没有。
</Callout>

```shell
cd gateway
go run ./cmd/gateway
```

</Steps>

当你将所有服务都启动之后：

- 前端访问入口始终是 http://localhost:3000
- 如果启用了网关，它用于 API / Hot News 等后端流量分流（例如 http://localhost:8787）
- 如果未启用网关，请把 `web/.env` 里的 `NEXT_PUBLIC_API_PREFIX`、`NEXT_PUBLIC_NOTIFICATION_WS_API_PREFIX`、`NEXT_PUBLIC_HOT_NEWS_API_PREFIX` 改成直连后端服务地址
